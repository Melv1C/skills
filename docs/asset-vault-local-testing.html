2. Auth model

  • Browser: Better Auth session cookie against /api/auth/*
  • Agents: API keys created under /api/tokens (or Better Auth api-key endpoints). Use either:
    • Authorization: Bearer av_…
    • x-api-key: av_…
  • Middleware normalizes Bearer av_… into x-api-key, then auth.api.getSession resolves a mock user session via enableSessionForAPIKeys.
  • Docs followed: api-key, bearer, prisma adapter.

4. Boot locally

1. Dependencies (Postgres + MinIO)

terminal A 
bun run docker:deps

MinIO API localhost:9000, console localhost:9001 (minioadmin / minioadmin). Bucket assets is created private by minio-init.

2. Env + Prisma

once / after schema changes 
bun run env:generate
bun run prisma:generate
bun run prisma:migrate

3. API

terminal B 
bun --filter backend dev
# or: cd apps/backend && APP_ENV=development bun run --hot src/index.ts

Listens on http://localhost:3000.

4. Web

terminal C 
bun --filter frontend dev
# or: cd apps/frontend && APP_ENV=development bun run dev

Vite on http://localhost:5173.

Useful URLs App http://localhost:5173 · Health http://localhost:3000/api/health

5. UI walkthrough

  1. Open http://localhost:5173/login → Sign up (email + password ≥ 8 chars).
  2. You land on /assets. Upload a file as public or private.
  3. Open the asset detail page → copy URL / markdown, toggle visibility, delete.
  4. Go to /settings/tokens → create a token named agent. Copy the av_… secret once.
  5. Paste that key into the curl flow below to confirm agent auth.

6. Agent / curl walkthrough

Replace $ASSET_TOKEN with a key from the UI (or create one via API while logged in).

Create a token (session cookie)

curl -sS -c /tmp/av.txt -b /tmp/av.txt \
  -X POST http://localhost:3000/api/auth/sign-in/email \
  -H 'Content-Type: application/json' \
  -d '{"email":"YOU@example.com","password":"YOUR_PASSWORD"}'

curl -sS -c /tmp/av.txt -b /tmp/av.txt \
  -X POST http://localhost:3000/api/tokens \
  -H 'Content-Type: application/json' \
  -d '{"name":"agent"}'

Upload (killer workflow)

curl -sS -X POST http://localhost:3000/api/assets \
  -H "Authorization: Bearer $ASSET_TOKEN" \
  -F "file=@./screenshot.png" \
  -F "visibility=public"

Expected JSON fields: id, url, markdown.

Public fetch

curl -sS -L -o /tmp/out.bin -w "%{http_code}\n" \
  "http://localhost:3000/a/<ASSET_ID>"

First response is 302 to a short-lived MinIO signed URL; -L follows it and downloads bytes.

Private requires auth

# without auth → 401
curl -sS -o /dev/null -w "%{http_code}\n" \
  "http://localhost:3000/a/<PRIVATE_ID>"

# with key → 302
curl -sS -o /dev/null -w "%{http_code}\n" \
  -H "Authorization: Bearer $ASSET_TOKEN" \
  "http://localhost:3000/a/<PRIVATE_ID>"

List / delete

curl -sS -H "Authorization: Bearer $ASSET_TOKEN" \
  http://localhost:3000/api/assets

curl -sS -X DELETE -H "Authorization: Bearer $ASSET_TOKEN" \
  http://localhost:3000/api/assets/<ASSET_ID>

7. Expected checks

Check Pass criteria
GET /api/health {"status":"ok","database":"connected"}
Signup / login Session cookie set; redirected to assets
Public upload via Bearer 201 + url/markdown; /a/:id redirects and serves bytes
Private upload Unauthed /a/:id → 401; with key → 302
Token revoke After revoke, uploads with that key fail auth
Delete Row gone; public URL stops working

8. Notes & caveats

  • Keep URL-like env vars non-sensitive in varlock (BETTER_AUTH_URL, PUBLIC_ASSET_BASE_URL, S3_ENDPOINT, S3_BUCKET) so response bodies / redirects are not blocked by leak detection. Secrets stay sensitive (BETTER_AUTH_SECRET, S3_*_KEY.
  • API key default rate limit is configured to 1000 req/hour in the plugin. Older keys created before that config may still have tighter DB defaults — create a fresh token if you hit 403.
  • GET /a/:id redirects to MinIO; browsers must reach localhost:9000. Production should keep the bucket private and only expose Hono.
  • App names remain backend / frontend (not renamed to api/web). No CLI, Redis, ACL table, or api-client package in v1.
  • Root scripts: docker:deps starts Postgres+MinIO; docker:db starts Postgres only.
