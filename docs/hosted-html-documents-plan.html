Hosted HTML documents: implementation plan

Reproduce Postplan’s agent HTML publishing inside api.skills.melvyn.be, drop the CLI, and retarget our skills to curl the same way asset-upload already does. Bytes and metadata stay on our infra.

Sources: postplan.dev, npm postplan@0.0.4 (src/api.js, src/html-policy.js, src/drafts.js), and this monorepo’s Asset Vault (Hono + Better Auth + Postgres + S3).

1. Goal

Agents write a self-contained HTML file and publish it. Today that is npx postplan upload, and the hosted URL lives on postplan.dev. We want the same product behavior, owned by us, with curl as the only agent interface.

  • New resource Document in apps/backend. Parallel to Asset. Not a fork of Postplan’s Express service.
  • Same auth as assets: Better Auth API keys (av_ / SKILLS_API_TOKEN). Metadata and HTML live in Postgres. S3 stays for Asset only (screenshots, video, PDFs).
  • No CLI, no ~/.postplan, no Shoo dashboard. Curl is the agent interface.
  • Skills in skills/ stop calling postplan.dev and call https://api.skills.melvyn.be.

2. What Postplan actually does

The npm package is both the hosted service and the CLI. Agents never talk HTTP directly. The CLI owns identity.

Upload path (CLI + API)

  1. CLI reads the local HTML file.
  2. Looks up ~/.postplan/drafts.json for absolutePath → draftId. Absent, or --new: omit draftId.
  3. POST /api/uploads with a JSON body: { html, filename, draftId?, description?, metadata }. Auth is optional (anonymous public uploads exist). Policy fail is HTTP 422.
  4. Server validates with parse5, writes S3 drafts/{id}/versions/{versionId}.html, inserts a version, updates drafts.current_version_id.
  5. Response: publicUrl + rawUrl. CLI writes the new draftId back into drafts.json.

Serve path

Every draft URL returns the uploaded HTML, byte for byte. No wrapper, no browser detection. /raw is an alias. Headers: X-Postplan-Draft-Id, X-Postplan-Draft-Version, plus a CSP that does not change the bytes (script-src 'none', connect-src 'none', form-action 'none', img-src https: data:).

Apex paths we copy the shape of: /d/:id, /d/:id/raw, /d/:id/v/:n, /d/:id/v/:n/raw. Wildcard subdomains (https://<id>.postplan.dev) we skip.

Why we do not need a CLI

Postplan’s CLI exists to hold local identity: path → draftId, plus a key in ~/.postplan/credentials.json. We already have keys (SKILLS_API_TOKEN). Path identity moves to the server as clientKey. Curl is then sufficient, same as assets.

4. Why not reuse Asset

Tempting: POST /api/assets already returns a public URL. Wrong primitive.

Need Asset today Document needs
Stable URL across content updates Every POST mints a new ULID. PATCH cannot replace bytes. Same id, new version, same /d/:id.
Agent fetch of the HTML itself 302 to a 5-minute signed S3 URL. Headers are S3’s. Canonical URL returns the HTML bytes from Postgres. CSP is ours. No expiry.
Blob store S3 required (50 MiB, signed URL delivery). Postgres TEXT. Cap is 512 KiB; we already serve through Hono, so S3 would be a second hop with no payoff.
Upload policy Any bytes, 50 MiB, any content-type. HTML only, 512 KiB, reject forms/frames/external scripts.
Version history None. /d/:id/v/:n plus latest.
Split of duties Assets stay screenshots, recordings, PDFs, binaries. HTML docs embed those via https://api.skills.melvyn.be/a/…. Documents are the HTML envelope. Do not upload HTML through /api/assets.

5. Decisions locked

Noun is Document, public path is /d/:id
Schema, routes, and skills say Document. Path prefix /d/ matches Postplan’s apex form. IDs are ULIDs, same as Asset, not nanoid.
No CLI
Agents use curl. Humans use the web UI. Do not add an npm bin, ~/.skills mapping file, or npx wrapper.
Multipart like assets, not Postplan’s JSON html field
file=@path;type=text/html plus form fields. Agents already know this from asset-upload. Do not accept a raw JSON html string in v1.
Server-side clientKey replaces ~/.postplan/drafts.json
Unique per (ownerId, clientKey). Skill sends clientKey=<absolute file path> on every upload. Same owner + same key appends a version and keeps the URL. Omitting clientKey always creates a new document.
forceNew reassigns clientKey
forceNew=true always inserts a new Document. If clientKey is also sent and already owned, null out the old row’s key in the same transaction, then attach it to the new document. Subsequent uploads of that path update the new URL. The old document stays reachable at its old id. This is CLI --new.
Uploads require auth; public read is the default
No anonymous Postplan-style uploads. Visibility defaults to public. private follows Asset rules: owner session or API key required on /d/:id.
Store HTML in Postgres, not S3
DocumentVersion.html is TEXT (UTF-8). Assets stay on S3. Documents are capped at 512 KiB, must be served through Hono with our headers, and are always read with their metadata. Putting them in S3 would add a two-phase write, orphan objects, and a second hop for zero delivery benefit (we already refused 302). One transaction: validate, insert version, commit. TOAST compresses the column. List/detail APIs must select without html.
Serve bytes through Hono, never 302
c.body(html, 200, headers) from the version row. Response is text/html; charset=utf-8 plus CSP. Do not redirect. Do not touch getStorage() on this path.
Inline classic script allowed at upload; CSP blocks execution
Match Postplan 0.0.4, not a “block all script” fork. External/module scripts, event handlers, forms, frames, and meta-refresh are rejected. Browser CSP uses script-src 'none'. Curl still gets the raw bytes.
512 KiB hard cap, reject-or-store
Env DOCUMENT_MAX_HTML_BYTES, default 524288. Do not share Asset’s 50 MiB limit. Do not rewrite or sanitize HTML. Policy fail is 400 with errors[] (assets style, not Postplan’s 422).
Hard delete, latestVersion denormalized
DELETE the Document row; versions cascade. No object-store cleanup. Store latestVersionNumber on Document so list queries do not aggregate and do not load html.
Skills source of truth is skills/ in this repo
Update html-communication, replace postplan-read, patch ai-review and asset-upload in the same change set as the API. Installed copies under ~/.agents/skills catch up on next install. Do not merge skill-only.

7. Data model

model User {
  // existing fields…
  documents Document[]
}

model Document {
  id                   String            @id
  ownerId              String
  owner                User              @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  clientKey            String?
  description          String?
  title                String?
  filename             String
  visibility           Visibility        @default(PUBLIC)
  latestVersionNumber  Int               @default(1)
  createdAt            DateTime          @default(now())
  updatedAt            DateTime          @updatedAt
  versions             DocumentVersion[]

  @@unique([ownerId, clientKey])
  @@index([ownerId, updatedAt])
  @@map("document")
}

model DocumentVersion {
  id               String   @id
  documentId       String
  document         Document @relation(fields: [documentId], references: [id], onDelete: Cascade)
  versionNumber    Int
  html             String   // TEXT, UTF-8. Never selected on list queries.
  sha256           String
  size             Int      // Buffer.byteLength(html, "utf8")
  hasInlineScript  Boolean  @default(false)
  createdAt        DateTime @default(now())

  @@unique([documentId, versionNumber])
  @@index([documentId, createdAt])
  @@map("document_version")
}
  • Postgres UNIQUE allows multiple NULL clientKeys for the same owner, so UI uploads that omit the key do not collide. No extra partial index needed.
  • html is Prisma String → Postgres TEXT, not bytea. We already require UTF-8 for parse5. TOAST stores and compresses values over 2 KiB. Do not gzip in the app.
  • Management list/detail must omit html (select the other version fields). Only GET /d/:id (and PUT/POST internals) load it. Do not return the body in JSON DTOs.
  • title is the latest version’s <title>, trimmed to 140 chars (Postplan). Fallback: filename, then "Untitled".
  • description max 200 in the API (short dashboard label). Postplan allowed 1000; we do not need that.
  • On delete: prisma.document.delete. Versions cascade. No storage cleanup.

Why not S3 for this resource

Asset Document
Cap 50 MiB 512 KiB
How clients fetch 302 to signed object URL API returns the bytes with CSP
Read with metadata? No (S3 is the CDN) Always (policy, version, owner check)
Write S3 then DB, compensate on failure One Postgres transaction

The “don’t put blobs in Postgres” rule is for unbounded files you would rather range-read or CDN. A 512 KiB HTML document that Hono must inspect and re-emit is a row, not a blob store object. Worst case 100 versions × 512 KiB = 50 MiB per document, before TOAST; realistic agent docs are tens of KiB and a handful of versions.

8. HTML policy

New module apps/backend/src/lib/html-policy.ts. Port Postplan’s validateHtml (parse5, scriptingEnabled: false). Validate before the insert. Dependency: parse5 on the backend package.

Reject (errors, HTTP 400)

  • Empty / whitespace-only document, or UTF-8 byte length above DOCUMENT_MAX_HTML_BYTES (that one is 413, not 400).
  • Tags from Postplan: form, iframe, object, embed, applet, base, link.
  • Extra tags our skill already forbids: frame, frameset.
  • <script src>. Script type other than empty, text/javascript, application/javascript (so module is rejected).
  • Attributes starting with on.
  • srcdoc.
  • URL attrs (href, src, action, formaction, poster, xlink:href) whose value, after stripping C0 whitespace, starts with javascript:, vbscript:, or file:.
  • <meta http-equiv="refresh">.
  • Inline CSS matching expression(, behavior:, or url(javascript:.
  • Nesting deeper than 512 (Postplan MAX_DEPTH).
  • Content-Type other than text/html / application/xhtml+xml, unless the filename ends in .html / .htm and type is missing or application/octet-stream.

Allow

  • Inline CSS in <style> and style="".
  • Inline classic <script> with no src and not module.
  • https: and data: images (so /a/:id embeds work).
  • Inline SVG.

Return shape

{ ok, errors: string[], warnings: string[], title: string | null, hasInlineScript: boolean }

Warning only: missing <title>. Do not fail the upload. Deduplicate error strings. Record hasInlineScript on the version. Do not rewrite the HTML.

Management routes

Method Path Auth Notes
POST /api/documents session or API key multipart: file required; clientKey, description, filename, visibility, forceNew optional. Upserts a version when clientKey matches.
PUT /api/documents/:id owner multipart file (optional description/visibility/filename). Always a new version of that id. UI path. Skills can ignore this and only POST.
GET /api/documents owner Cursor pagination like assets (cursor, limit 1–100, default 20). Newest updatedAt first.
GET /api/documents/:id owner Metadata plus versions array, newest version first.
PATCH /api/documents/:id owner description, visibility, filename. Not bytes.
DELETE /api/documents/:id owner Document + cascaded versions. { "success": true }.

POST /api/documents behavior

  1. Parse multipart. Require file as a File.
  2. Read bytes. 413 if over cap. Decode UTF-8. Run html-policy. 400 { error, errors } on failure.
  3. Normalize forceNew as true when the field is "true" or "1".
  4. If not forceNew and clientKey is non-empty, look up (ownerId, clientKey).
  5. Hit: next version = latestVersionNumber + 1. In one transaction, insert the version (including html), update title/filename/latestVersionNumber/updatedAt. Update description only if the field was sent. HTTP 200.
  6. Miss, or no clientKey: create Document + version 1 in one transaction. HTTP 201.
  7. forceNew: in a transaction, if clientKey is set, UPDATE … SET clientKey = null on the previous owner row, then insert the new document with that key. HTTP 201.
  8. Unique-constraint race (two concurrent POSTs with the same clientKey): retry once as an update. No orphan objects to clean.

10. Public serving

apps/backend/src/routes/public-document.ts, mounted at /d next to /a in index.ts. One handler for canonical and /raw.

  • Resolve document + version (latest, or :n if integer ≥ 1).
  • 404 JSON { error: "Document not found" } if missing. No HTML 404 page.
  • If PRIVATE, same session/API-key owner check as public-asset.ts.
  • Load version.html only. c.body(html, 200, headers) with Content-Type: text/html; charset=utf-8. Do not call storage. 
Content-Type: text/html; charset=utf-8
X-Content-Type-Options: nosniff
X-Skills-Document-Id: 01KZV…
X-Skills-Document-Version: 2
Cache-Control: no-store                                 # latest
Cache-Control: public, max-age=31536000, immutable      # /v/:n only
Content-Security-Policy:
  default-src 'none';
  script-src 'none';
  style-src 'unsafe-inline';
  img-src https: data:;
  font-src data:;
  connect-src 'none';
  form-action 'none';
  frame-ancestors 'none';
  base-uri 'none'

CSP does not change the bytes. img-src https: is required so /a/:id embeds work. font-src data: covers inline font data URLs some mocks use. Latest is no-store so a re-upload is visible without waiting on caches (Postplan sets no-store globally).

Route order: register /d/:id/v/:n/raw and /d/:id/v/:n before /d/:id/raw and /d/:id, or use a single param parser that treats a trailing raw as an alias.

Implementation notes that match existing code

  • IDs: ulid(), same as createAsset.
  • Hash: createHash("sha256").update(html, "utf8").digest("hex"). size is Buffer.byteLength(html, "utf8").
  • Auth on management routes: .use("*", isAuthenticated) like assetRoutes.
  • Multipart: c.req.parseBody({ all: true }), require file instanceof File. Decode with await file.text() (UTF-8).
  • List cursor: orderBy [{ updatedAt: "desc" }, { id: "desc" }], take: limit + 1, skip 1 on cursor. Assets order by createdAt; documents should use updatedAt so a re-upload bubbles up.
  • Do not import getStorage from document routes or services. Assets keep using it.
  • List/get DTOs never include html. Prisma queries for those paths must omit the column.
  • No test runner is wired today. Add bun:test files next to the modules. Run with bun test from apps/backend. Do not introduce Jest/Vitest.

18. Definition of done

  1. From a machine with SKILLS_API_TOKEN, the html-communication curl creates a public URL on api.skills.melvyn.be.
  2. Repeating the same curl with the same clientKey returns the same id and increments version.
  3. curl of url and of rawUrl returns the uploaded HTML (status 200, not 302), with CSP and document headers.
  4. A second agent can html-document-read that URL and continue from the file contents.
  5. A document that embeds /a/:id images still shows them in a browser.
  6. Policy rejects a <form> upload with a 400 and a useful errors array.
  7. ai-review reports no longer mention Postplan as the host.
  8. No new npm CLI. No secrets in published HTML. HTML lives in Postgres TEXT, not S3.

19. Risks and cutover

Skills go live before the API
Agents 401/404. Ship API to production first, then update skills, or ship both and install skills only after deploy. Do not merge skill-only.
clientKey is an absolute path, so it is machine-specific
Same limitation Postplan had with drafts.json. Accept it. Two laptops uploading the “same” file get two documents unless they share an id via PUT. Do not hash file contents for identity (content-addressing would collapse unrelated docs that happen to match).
Existing review URLs stay on postplan.dev
Fine. html-document-read still fetches those during transition. New work goes to our API. No backfill.
Inline script + CSP mismatch surprises authors
Document it in html-communication: inline classic script may be present for no-JS fallback, but it will not run in a browser on our host. If a mock needs to run script, it will not, by design. That matches Postplan.
Accidentally returning html on list/detail
Default Prisma includes would pull every version body into the JSON API. Use explicit select / omit html on management queries. Public /d is the only reader of the column besides insert.
Postgres growth
Acceptable at this cap and audience. If a later tenant uploads thousands of max-size versions, add a retention trim (keep last N) rather than moving to S3. Do not premature-optimize with object storage.
Concurrent upsert of the same clientKey
Unique constraint on (ownerId, clientKey). Catch the Prisma unique violation and retry as an update once. The failed insert rolls back with the transaction; nothing else to delete.
Installed skills lag the repo
Agents read ~/.agents/skills and ~/.cursor/skills-cursor, not this repo’s skills/ until reinstall. After production deploy, copy or reinstall those four skills before expecting agents to hit the new API. Until then, html-communication still uploads to postplan.dev.
